## [0.5.0] - Unreleased

### Changed

- **Breaking:** `ConfigError` and its struct variants (`IoError`, `YamlError`, `JsonError`, `TomlError`, `DeserializeError`) are now `#[non_exhaustive]`. A `match` from another crate needs a `_ => ...` arm, and a struct variant's fields are bound with a trailing `..` — `ConfigError::IoError { file, source, .. }`. This is the last release in which it can be done without a major bump, and the cost of not doing it is already visible: this same version added `DeserializeError`, and `JsonError` / `TomlError` exist only with their features, so the variant list varies by build. Each of those would otherwise silently break any consumer matching exhaustively. `PathNotFound` and `FormatError` are deliberately exempt: they carry one `String` that nothing could be added to, so `ConfigError::PathNotFound(path)` keeps binding the path directly.
- **Breaking:** `ConfigError` is now derived with `thiserror`, and the `IoError`, `YamlError`, `JsonError` and `TomlError` variants are struct variants carrying the offending filename and the original underlying error instead of stringified messages: `{ file: Option<String>, source: ... }` (`file` is `None` when parsing from a string). `std::error::Error::source()` now returns the wrapped error, and Display messages include the filename when known (e.g. `YAML parse error in config.prod.yaml: ...`). Match with `ConfigError::YamlError { file, source, .. }` or `ConfigError::YamlError { .. }` — the trailing `..` is required, see the `#[non_exhaustive]` entry below.
- **Breaking:** the `JsonError` and `TomlError` variants now only exist when the corresponding feature is enabled (they carry `serde_json::Error` / `toml::de::Error`). Code matching on them without the feature no longer compiles — such code was unreachable anyway.
- **Breaking:** `Config::default()` now **panics** if `config.yaml` exists but cannot be read or parsed, instead of silently returning an empty config. A missing file still yields an empty config (it is shorthand for `Config::load_optional("config.yaml", "/", None)`, which already treats "not found" as empty). Previously a malformed or unreadable `config.yaml` was silently ignored, contradicting the documented `load_optional` philosophy that a present-but-broken file should be surfaced. Use `Config::load_optional` / `Config::load_required` to obtain the error as a `Result`.
- **Breaking:** a path separator containing a backslash is now rejected with `ConfigError::FormatError` by every constructor, alongside the existing empty-separator check. `\` is the escape character in path syntax, so the splitter tested for an escape sequence before it tested for the separator: a separator of `\` was consumed as an escape and never matched. Construction succeeded, the document was fully populated, and then *every* lookup returned `None` / `""` / `[]` with no error raised anywhere — `Config::load_yaml("a:\n  b: 42", "\\").get_int("a\\b")` was `None`, which is the worst failure shape a config library has. Any backslash is rejected, not only a leading one, so the rule is simply "the separator may not contain the escape character". Other unusual separators are unaffected: `::`, `->` and even `{env}` continue to work.
- Path splitting no longer allocates a `String` per segment. `parse_path` returned `Vec<String>`, so every accessor call allocated one `String` per path segment plus the `Vec` — for `db/redis/port`, four allocations per lookup. Segments are now yielded lazily as `Cow<str>`, borrowing directly from the path and copying only for a segment that actually contains an escape sequence, which real paths almost never do. Measured on the benchmark suite: `str("a/b/c")` is ~2× faster (219 ns → 109 ns), `contains` ~2.5×, and a 30-segment path 2.3× (1.53 µs → 664 ns). Paths whose every segment is escaped still gain ~15% from dropping the `Vec`. No API or behaviour change.
- **Breaking:** empty path segments are now rejected instead of skipped. `get_leaf` skipped them, so `a//b`, `/a/b` and `a/b/` all resolved exactly like `a/b`, and a path of just the separator skipped every segment and returned the **entire document** — making `contains("/")` true and `get("/")` yield the root. Every segment must now be non-empty: the lenient accessors return `None` / `""` / `[]` and the strict ones return `PathNotFound` naming the path as written. This turns typos that previously succeeded silently into visible failures. A key that genuinely contains the separator is still reached with an escape sequence (`db/host\/port`), which is unaffected. `fmt`'s `base` argument follows the same rule, with one deliberate exception: an empty `base` still means "the keys are at the top level", which is distinct from a base of just the separator. `fmt` also stopped carrying its own near-duplicate of the path-navigation loop and now shares `get_leaf`.
- `deserialize` / `deserialize_strict` / `get_as` / `get_as_strict` no longer clone before deserializing. They previously called `yaml_serde::from_value`, which takes `Value` by value, so every call deep-cloned the whole document (`deserialize_strict`) or the target subtree (`get_as_strict`) purely to hand it over. `yaml_serde` implements `Deserializer` for `&Value`, so these now deserialize straight from the borrowed tree. Measured with the new benchmark suite: `deserialize_strict` is ~3× faster at every config size (58.9 µs → ~17.5 µs on a 100-section config), and `get_as_strict` ~2.5× faster. No API or behaviour change. `get` / `get_strict` still clone, which is inherent to returning an owned `Value`; their docs now point at `get_as_strict` for the no-clone path.
- **Breaking:** `{env}` handling is no longer asymmetric. Supplying an environment for a filename that has no `{env}` placeholder used to be a hard `FormatError`; it now loads the file as given and still records the environment. This made the documented `config!` block syntax unusable in its own README form — `config! { file: "config.yaml", env: "prod", merge: ["config.{env}.yaml"] }` applies the same `env` to every filename, so the base file, which has no placeholder, failed the load. Conversely, a filename containing `{env}` with no environment supplied used to be passed to the OS verbatim and fail as a missing file literally named `config.{env}.yaml`; it now returns a `FormatError` naming the placeholder. The rule is now one-directional: an environment supplies a value for `{env}` if the filename uses it, and a placeholder with nothing to substitute is an error.
- `reload_from` now accepts an `{env}` placeholder, resolved against the environment the config already carries — it has no `env` argument because it preserves the existing one. Previously the placeholder was passed through untouched and the file open failed. The resolved filename is recorded, so a later `reload()` reads the same file.
- **Breaking:** environment variable interpolation gained an escape and nesting. `$${` now produces a literal `${`, so a value that must contain placeholder syntax can be written directly — previously there was no way to express one, and `$${VAR}` expanded to `$` followed by `VAR`'s value. The escape is deliberately narrow: only `$${` is special, so `$100`, `Pa$$w0rd!` and other lone or doubled dollars are untouched. Placeholders are now matched by brace depth instead of stopping at the first `}`, so defaults may nest: `${A:-${B:-c}}` falls through each level in turn, where previously it parsed the default as the broken fragment `${B:-c`. Nesting inside the *variable name* (`${${PREFIX}_HOST}`) is rejected with a message saying so, rather than reaching `env::var` as a literal and failing with a confusing "not set". Nested defaults are capped at 32 levels — deeper than any legitimate config, and far enough below the point where the recursion would overflow the stack and abort the process instead of returning a `FormatError`.
- **Breaking:** `fmt` / `fmt_strict` now parse the format string properly instead of running `replacen("{}", ..)` once per key. Three consequences. (1) A literal `{` or `}` in the output must now be written `{{` or `}}`, as in `std::format!`. (2) A mismatch between placeholder count and key count is now an error — previously a surplus placeholder was left in the output verbatim and a surplus key was silently dropped, so `fmt("{}{}", base, &["a"])` returned `"value{}"` and `fmt("{}", base, &["a", "b"])` discarded `b`. `fmt_strict` returns `FormatError`; `fmt` returns an empty string. (3) Indexed placeholders `{N}` are now supported, so keys can be reordered and reused: `fmt("{1}/{0}/{1}", base, &["a", "b"])`. Auto-numbered and indexed placeholders may be mixed.
- **Fixed:** `fmt` / `fmt_strict` no longer rescan substituted values. Because each key was applied with `replacen` over the accumulating result, a config value containing `{}` became a placeholder for the *next* key — `fmt("{}-{}", base, &["a", "b"])` with `a = "x{}y"` returned `"xBy-{}"` instead of `"x{}y-B"`. Values are now resolved up front and written into the output directly, so they are never reinterpreted.
- Added a `criterion` benchmark suite in `benches/config.rs`, run with `cargo bench`. Five groups, 26 cases: path traversal by depth (with and without escape sequences), typed access (`deserialize_strict` / `get_as_strict` / `get_int`) across config sizes, `load_yaml` by document size, and `reload` with and without an overlay. `criterion` is a dev-dependency, so it does not appear in downstream dependency trees; it is pulled without default features (keeping `cargo_bench_support`) to avoid the plotters/rayon tree. The benchmarks exercise the public API only, which is also what makes them meaningful — `str(path)` measures path splitting and tree navigation together, the way callers pay for it.
- `parse_path` — the path splitter behind every accessor call — no longer collects the remainder of the path into a fresh `String` at each backslash and each separator candidate. It now walks the path as a shrinking `&str` suffix and tests it with `strip_prefix`, allocating nothing while scanning. The old scan was quadratic in path length; measured on a 100-segment path it is ~7.3× faster (51.4 µs → 7.0 µs), and ~2× on a typical 3-segment path (274 ns → 140 ns). Segment strings are also moved out with `mem::take` instead of being cloned. No behaviour change.
- `ConfigHandle` now mirrors the complete lenient accessor surface of `Config`. Added `get`, `list`, `get_as`, `deserialize` and `fmt` alongside the existing `str`, `contains`, `get_int`, `get_float` and `get_bool`. Previously half the lenient API was reachable only via `read()`. The `*_strict` variants and the metadata accessors (`get_filename`, `environment`) are deliberately not mirrored — `read()` gives access to every `Config` method, and the strict variants are used in contexts that already bind a snapshot.
- **Breaking:** `ConfigHandle::read` now returns `Arc<Config>` — an immutable snapshot — instead of `RwLockReadGuard<'_, Config>`. `Arc<Config>` derefs to `Config`, so ordinary usage such as `handle.read().get_int("app/port")` and `let cfg = handle.read();` is unaffected; only code that names the `RwLockReadGuard` type explicitly needs updating. The handle now stores `Arc<RwLock<Arc<Config>>>`, so `read` holds the lock only long enough to clone an `Arc`. Previously the returned guard held a read lock for as long as the caller kept it, which blocked every `reload` for that entire duration. A snapshot is also stable across a concurrent reload, so several reads from one snapshot can never straddle a reload — take one snapshot when you need multiple values to agree.
- `ConfigHandle::reload` no longer holds the write lock across disk I/O and parsing. It now copies the config's source list (base filename plus the overlay chain) under a read lock, builds the new config with no lock held, and takes the write lock only to swap the finished config in. Readers previously blocked for the full duration of every file read and parse; they now block only for the swap. Failure behaviour is unchanged — if the reload fails, no swap occurs and the existing config is preserved.
- JSON/TOML → YAML value conversion failures (previously stringified into `JsonError`/`TomlError`) now surface as `YamlError`, since the conversion happens in the YAML layer. Parse errors still surface as `JsonError`/`TomlError`.
- `get_leaf` returns a borrowed `&Value` instead of deep-cloning the subtree on every access. `contains`, `str`, `list` and the typed accessors no longer clone; only `get`/`get_strict` and `get_as`/`get_as_strict` clone, where an owned value is actually produced. No public API changes.
- Added a crate-level doc comment. `src/lib.rs` had none, so the docs.rs landing page was bare despite the README: it now covers loading, the lenient/strict split, path syntax, layering and reloading, environment interpolation and the feature flags, with compiled examples. The README deliberately remains the long-form guide and is not included as crate docs — the hidden-line scaffolding needed to compile its examples as doctests renders literally on GitHub and crates.io.
- Added `#![warn(missing_docs)]`, and documented the six items it flagged: the crate itself, `Config`, and the `source` field of the four `ConfigError` struct variants (public API since `dbf152f`).
- Added `rust-version = "1.85"` (MSRV) to `Cargo.toml`, so Cargo diagnoses a too-old toolchain instead of failing with a confusing compile error. The floor comes from the dependency tree — indexmap 2.14 via yaml_serde, and toml 1.1 — not from this crate's own code. Dev-dependencies require more (criterion 0.8 needs 1.86), so `cargo bench` has a higher floor than using the library.
- Added `[package.metadata.docs.rs] all-features = true` so the feature-gated JSON/TOML APIs appear in the docs.rs documentation.
- Documented three behaviours that were previously unstated, none of which change: paths navigate **mappings only**, so `items/0` is a lookup for a key named `0` rather than a sequence element (read sequences whole with `list`, `get_as` or `deserialize`); `load_or_create` creates the file but **not** its parent directories, so a missing parent is an `IoError` rather than a conjured directory tree; and `env` is interpolated into a filesystem path **without validation**, so it must not come from an untrusted source. Each is now stated in the README and in the relevant rustdoc, and pinned by a test.
- README: removed the duplicated "Thread Safety" section (merged into "Thread-Safe Shared Config") and documented the `load_or_create` defaults-format behaviour.
- Tests no longer write fixture files into the crate's working directory. All file-based tests now use per-test temp directories (via a new `tempfile` dev-dependency) that are cleaned up automatically, even when a test panics. Previously, fixed-name files like `test_handle_reload.yaml` were created in the CWD and left behind on failure.
- Tests that mutate process environment variables (`std::env::set_var` / `remove_var`) are now serialized through a shared lock in a new internal `test_util` module, eliminating races under the parallel test runner.
- Internal restructure: the 1,108-line `src/config/mod.rs` has been split into focused submodules — `loader` (constructors), `accessor` (value reading), `merge`, `reload`, `path` (path parsing/navigation), `env` (variable interpolation) and `fmt`. `mod.rs` now holds only the `Config` type, its `Default` impl and the metadata accessors. Private helpers that never took `self` (`get_leaf`, `parse_path`, `merge_values`, `resolve_env_vars`, `get_file`, `load_auto`, `to_string`) are now free functions in their respective modules. The YAML/JSON/TOML adapters moved into a `parser` submodule alongside the extension-based `load_auto` dispatch, so the format feature gates live in one place and the loader no longer needs to know which formats exist. Every constructor now funnels through a single private `from_parsed` builder and a shared `check_separator` guard, replacing seven copies of the `Config { .. }` literal and five copies of the empty-separator check. No public API, behaviour or documentation changes.

### Added

- docs.rs now labels the feature-gated items. `[package.metadata.docs.rs]` set `all-features = true`, which makes docs.rs *build* `load_json`, `load_json_file`, `load_toml`, `load_toml_file`, `JsonError`, `TomlError` and the matching `ConfigError` variants — but with no `doc_cfg` they rendered alongside `load_yaml` with nothing to indicate they need a feature flag, so a reader reasonably assumed they were always available. Adds `rustdoc-args = ["--cfg", "docsrs"]`, `#![cfg_attr(docsrs, feature(doc_cfg))]` and a `#[cfg_attr(docsrs, doc(cfg(feature = "...")))]` beside each gated public item. The nightly-only feature is requested behind a cfg that only the docs.rs build sets, so the MSRV and ordinary builds are untouched. `check.ps1 -Docsrs` reproduces that build locally, since it is the only configuration in which those attributes compile.
- `ConfigHandle::reload_from(filename)` — switches a live handle to a different config file, clearing the overlay chain, with every clone following the switch. `Config::reload_from` takes `&mut self` and `ConfigHandle::read` yields only `&Config` (via `Arc`), so there was previously no route to it from a live handle at all: a handle was bound to its file for life while a bare `Config` was not, and the type's own docs promised that `read()` "gives access to every `Config` method". It uses the same discipline as `reload` — resolve and parse with no lock held, take the write lock only for the swap, and hold the reload lock throughout so the two order against each other. On failure no swap occurs. The `merge_*` builders remain unmirrored by design: they consume `self` and belong to constructing a config, before it goes into a handle.

### Fixed

- **JSON and TOML configs now keep their document key order instead of arriving sorted alphabetically.** `serde_json::Value` and `toml::Value` both store objects in a `BTreeMap` unless their `preserve_order` feature is enabled, and this crate parsed through both — so the order was lost inside the parse, before any of this crate's code saw the document. Two documented guarantees were therefore true only for YAML: `outline`'s "keys appear in document order, the same order the merge preserves", and the merge's own key-order preservation, which went to real trouble (`Mapping::remove` is `swap_remove`, so overrides are merged in place) to preserve an order the file never had. Visible to anything order-preserving — deserializing into a `Mapping`, an `IndexMap` or a `Vec<(K, V)>`, `outline`, and any re-serialization downstream — including in a chain that mixes formats. The two halves are fixed differently, on purpose. TOML enables the `toml` crate's `preserve_order`, since the datetime handling above has to go through `toml::Value`. JSON instead deserializes straight into this crate's value model, whose `Mapping` is already `IndexMap`-backed: cargo features are additive across the whole dependency graph, so switching on `serde_json`'s `preserve_order` here would have changed `serde_json::Value`'s iteration order for every other crate in a consumer's build. Neither change adds a dependency — `indexmap` is already in the tree via `yaml_serde` — and the MSRV is unmoved at 1.85, verified with `cargo +1.85 check` on all features and none.
- **Breaking (`json` feature):** a duplicated key in a JSON config is now an error instead of silently taking the last occurrence. This follows from the key-order fix above rather than being sought separately: parsing into this crate's value model instead of `serde_json::Value` inherits that model's rejection of a duplicate entry, where `serde_json`'s map simply overwrote. YAML and TOML have always rejected duplicates, so this is the three formats agreeing about the same mistake rather than a new rule — and a duplicated key in a config file is a copy-paste error in JSON exactly as it is in the other two. The error is a `ConfigError::JsonError` naming the key and its position.
- JSON parsing no longer converts through an intermediate `serde_json::Value`, which also drops a fallible step: `yaml_serde::to_value` returned a `Result`, so a `.json` file could fail with a `YamlError`. JSON parsing now reports `JsonError` or nothing at all — the same cleanup made to the TOML path below. Trailing content after the document is still rejected, since this goes through `serde_json::from_str` rather than a hand-driven `Deserializer`.
- **Environment variables are now interpolated inside YAML-tagged values.** `resolve_env_vars` matched `String`, `Mapping` and `Sequence` and returned everything else untouched, so `Value::Tagged` — YAML's `!Tag`, which is how serde spells an enum variant — fell into the catch-all along with the entire subtree beneath it. Two silent consequences. A variable that *was* set was not substituted, so `db: !Postgres` / `password: ${DB_PASSWORD}` served the literal text `${DB_PASSWORD}` to whatever consumed it. Worse, a variable that was *not* set no longer errored: `${VAR}` with no default is the one place this crate fails fast, and a tag anywhere above it disabled that guarantee for everything under it, turning a stop-the-deployment error into a plausible-looking value that fails somewhere else much later. Tags are now recursed into, with the tag preserved. The tag itself is never interpolated, by the same reasoning that exempts keys — it selects a variant, so interpolating it would make the document's shape depend on the environment. (YAML's tag syntax rejects `$` and `{`, so this is enforced by the format in any case.)
- **A `!Tag`ged subtree is now deep-merged rather than replaced wholesale.** `merge_values` matched `(Mapping, Mapping)` and fell through to "overlay wins" for everything else, so an overlay under the same tag as the base replaced it entirely and silently dropped every sibling key the overlay did not restate — the one place the deep merge this crate promises quietly stopped being deep. Two values under the *same* tag now merge like the mappings they usually are. A differing tag still replaces, as does an untagged overlay onto a tagged base: the tag names the variant, so changing or dropping it is a change of shape rather than a patch, and merging the fields of two variants would produce a document belonging to neither.
- **A `!Tag` no longer hides values from the accessors, `outline` or `Debug`.** Following from the two above, since the same variant went unhandled in every walker. The value model untags when *indexing*, so `db/host` always resolved through a tag — but the readers did not agree: `str` on a tagged scalar returned `""`, `get_int` / `get_bool` reported "is not a number" / "is not a boolean", `list` returned `[]`, `outline` printed a tagged mapping as `db: <value>` and hid its addressable keys, and `Debug` described it as `<scalar>`. A tag is now transparent to reading and addressing everywhere, and preserved for deserializing: `get` and `get_as` still see it, because selecting the enum variant is what it is for. The three walkers that used to end in a catch-all (`resolve_env_vars`, `describe_leaf`) now match `Value` exhaustively — it is not `#[non_exhaustive]`, so a variant added upstream is a compile error rather than a fourth repeat of this bug.
- **Breaking (`toml` feature):** TOML datetimes are now read as strings instead of leaking the `toml` crate's internal serde protocol. TOML has a date-time type and serde's data model does not, so `toml_datetime` works around it by serializing a datetime as a one-field struct with a private marker name, expecting its own deserializer to recognise it on the way back. This crate converted through `yaml_serde::to_value`, which has never heard of the marker and so faithfully materialized the workaround: `started = 2024-01-01T00:00:00Z` became the mapping `{"$__toml_private_datetime": "2024-01-01T00:00:00Z"}`. Every accessor then misreported one of TOML's four scalar types — `str` returned `""` for a value plainly present in the file, `str_strict` called it "not a scalar", `get_as` into any struct with a `String` field failed with "invalid type: map, expected a string", and `outline` printed `s/started/$__toml_private_datetime: <string>`, advertising a transitive dependency's field name as an addressable config path. A datetime is now the text the file contained — RFC 3339 for an offset date-time, and TOML's own forms for the local date, time and date-time variants — so it behaves as a scalar like any other and deserializes into a `String` or into `chrono`/`time`/`jiff`'s date types. The one thing it no longer deserializes into is `toml::value::Datetime`, which recognises only the marker mapping; that type can only be named by taking a direct dependency on `toml`, which this crate already advises against because a version differing from the resolved one produces two incompatible `Value` types.
- TOML parsing no longer converts through serde at all. `toml::Value` is now walked into the crate's value model by an explicit exhaustive match rather than `yaml_serde::to_value`, which is what makes the datetime fix possible and drops a fallible step with it: `to_value` returned a `Result`, so a `.toml` file could fail with a `YamlError`. TOML parsing now reports `TomlError` or nothing at all. `toml::Value` is not `#[non_exhaustive]`, so a variant added upstream is a compile error here rather than another silent fallthrough — which is how the datetime case went unnoticed through four review passes. Key order is unchanged: the `toml` crate stores tables in a `BTreeMap` unless its `preserve_order` feature is enabled, and the old conversion iterated the same map.
- `merge_required` / `merge_optional` no longer discard the environment they are given. Both called `get_file(filename, env)` and dropped the returned environment on the floor, so the natural layered shape — an environment-agnostic base with an environment-specific overlay — resolved the overlay's `{env}` correctly and then forgot it: `environment()` under-reported, and `reload_from`, which takes no `env` argument precisely because it reads the one on the config, could not resolve a template the merge had resolved a moment earlier. A merge now records the environment **if the config does not already carry one**; one set by a constructor is never replaced, since letting an overlay reassign it would silently change what a later `reload_from` resolves. `reload()` was unaffected either way, as it stores resolved overlay names.
- `outline`'s key escaping now guards against an empty separator, which would otherwise match at every position without advancing — an infinite loop that also grew the output string until it exhausted memory. Not reachable through the public API (`check_separator` runs in every constructor, and `sources()` only clones), but the path splitter states the identical backstop explicitly, and two functions with the same hazard disagreeing about whether it is worth restating leaves the next reader to work out which one is right.
- Environment variable resolution no longer conflates "not set" with "set, but not valid Unicode". `env::var` returns `Err` for both, and a wildcard treated them identically, so a variable that *was* set but held non-Unicode bytes produced one of two wrong outcomes: without a default, an error stating it "is not set" — sending the operator to verify an export that was already correct; with a default, the fallback applied **silently**, running the deployment on the wrong value while they believed their setting had taken effect. `VarError::NotUnicode` is now matched separately and returns a `FormatError` naming the real cause, without consulting the default. Set-but-unreadable is not an absence, by exactly the reasoning already applied to set-but-empty.
- `ConfigHandle::reload` no longer loses an update when two reloads overlap. The read and parse deliberately happen with no lock held, but nothing serialized two reloads against each other, so both built a complete config off to the side and the **slower** one swapped last — leaving the handle serving a superseded document indefinitely, after two calls that both returned `Ok`. It takes two call sites that can reload independently: a debounced file watcher firing twice on one write, or a watcher alongside a SIGHUP handler. A dedicated `Mutex` is now held for the whole of `reload`, so a second reload waits for the first rather than racing it. The property the lock-free design exists to protect is unchanged — that mutex is never taken by `read` or any convenience accessor, so readers still never block on disk I/O.
- `config!` now compiles when invoked by its full path, `trail_config::config! { .. }`. The block arm recursed into the crate's own macro unqualified (`config!(@sep ...)` / `config!(@env ...)`), and `macro_rules!` expansion resolves at the call site — so it compiled only for callers with `use trail_config::config;` in scope and failed with `error: cannot find macro 'config' in this scope` otherwise. Both recursions are now `$crate::config!(...)`. The four positional arms expand to `$crate::Config::...` directly and were never affected. Every existing test imported the macro by name, which is why the suite passed over it; `tests/macro_path.rs` deliberately does not.
- A leading UTF-8 BOM is now stripped before parsing, for every format and for strings as well as files. `serde_json` rejects a BOM where `yaml_serde` and `toml` skip it, so the same bytes loaded as `.yaml` and `.toml` but failed as `.json` with `expected value at line 1 column 1` — pointing at line 1 of a file that looks correct in every editor. This is a Windows-shaped trap: PowerShell's `>`, `>>` and `Out-File` write UTF-8 **with** BOM by default, so a config produced by a setup script carried one. Only a leading BOM is removed; U+FEFF elsewhere is a legitimate zero-width no-break space and stays in the document.
- Documentation: `Config` was described as not being `Send + Sync`, in both the rustdoc and the README. It is — and `ConfigHandle`'s `Arc<RwLock<Arc<Config>>>` could not be `Sync` otherwise. The claim pushed callers toward a handle for the share-but-never-reload case, where a plain `Arc<Config>` is sufficient and cheaper, and it misdescribed what `ConfigHandle` provides: interior mutability (replacing the document behind shared references, which `reload` taking `&mut self` otherwise prevents), not thread-safety.
- `load_optional` now records the resolved filename when the file is missing, instead of discarding it. The not-found branch built the empty config with `""` as its filename, so the returned `Config` had no source at all and `reload()` — which refuses to run without one — failed permanently with `FormatError: Cannot reload: no file path associated with this config`, even after the file appeared on disk. A config loaded optionally before its file exists can now pick it up on a later `reload()`. While the file is still absent, `reload()` returns `IoError` (`NotFound`) and leaves the config unchanged, matching the behaviour of every other missing base file. `get_filename()` consequently returns the resolved name (with `{env}` substituted) for such a config; `""` now means only "parsed from a string".

- `load_or_create` now parses the defaults string according to the file's format (JSON/TOML by extension, YAML otherwise) instead of always parsing it as YAML, and the created config now records its filename — previously `reload()` failed with `FormatError` after a first-run creation.
- Environment variable placeholders are no longer re-resolved over the entire merged tree on `merge_required` / `merge_optional`. Previously the already-resolved base config was scanned again after every merge, so a variable whose *value* contained placeholder syntax (e.g. a password like `pa${ss}word`) would load fine but break — or double-expand — on the next merge. Each file is now resolved exactly once, when it is loaded.
- `reload()` now resolves environment variables per file (base and each overlay) before merging, matching the load-then-merge path. Previously it resolved once over the final merged tree, which could produce different results than the original load for values containing `${`.
- `reload_from` no longer leaves the config in an inconsistent state when the switch fails. It assigned `self.filename` *before* environment variable resolution could fail and cleared `self.overlays` only afterwards, so a file that parsed but contained an unresolvable placeholder (unset variable with no default, unclosed `${`) left the config holding the **new** filename, the **old** content and the **stale** overlay chain — a later `reload()` then re-read the wrong file and re-applied overlays that no longer belonged. The new file is now read, parsed and resolved into a local first, and filename, content and overlays are committed together only on success. This restores the documented "existing configuration is preserved unchanged" guarantee, which `reload_from`'s doc comment now states explicitly. The missing-file and parse-error paths were already correct, since they returned before any assignment.
- `fmt` / `fmt_strict` now name a missing key using the config's own separator instead of a hardcoded `/`. A config using `::` reported `db::redis/port` — a path that does not exist in the caller's addressing scheme. An empty `base` (meaning "the keys are at the top level") now yields just the key rather than a leading separator. This was the one place `fmt` still assumed `/` after the `get_leaf` unification.
- `Debug` on `Config` and `ConfigHandle` no longer prints the resolved document. Both were derived, so `{:?}` dumped the whole config tree — and a config crate is precisely where `${DB_PASSWORD}` and `${API_TOKEN}` get interpolated, with the real values already substituted in by the time `Debug` runs. A panic message, a `tracing` span, an `anyhow` context chain or a `#[derive(Debug)]` on any struct holding a `Config` put them in cleartext. Both now print the filename, separator, environment and overlay chain, with the document elided as `content: <N keys>`. Filenames are kept: they are not secrets, and the overlay chain is what you want when a reload misbehaves. `ConfigHandle` formats via `try_read`, so `{:?}` can never block against a reload; in the rare case the write lock is held it prints `config: <locked>`. This is a visible output change, not an API change.
- Deep merge no longer scrambles mapping key order. `yaml_serde::Mapping` wraps an `IndexMap` and is insertion-ordered, but its `remove` is `swap_remove`, so the remove-then-insert in `merge_values` moved the map's *last* entry into the vacated slot and appended the overridden key at the end — two keys displaced for a single-key overlay, and a merged shape that depended on the order of the overlays. Values are now merged in place via `get_mut`, so an overridden key keeps its position, genuinely-new overlay keys are appended, and a hash lookup plus the removal churn is saved per overridden key. Invisible through the scalar accessors, but visible to anything order-preserving: `get_as` / `deserialize` into a `Value`, a `Mapping`, an `IndexMap` or a `Vec<(K, V)>`, and any re-serialization downstream.
- **Breaking:** deserialization failures now surface as a new `ConfigError::DeserializeError { file, path, source }` instead of `YamlError`. `get_as_strict` and `deserialize_strict` mapped their failures through `From<yaml_serde::Error>`, so a config loaded from `config.toml` reported `YAML parse error: missing field ...` — naming a format the caller never used, and a phase that had already succeeded. Mechanically the old variant was true, since deserialization runs through the `yaml_serde` value model whatever the source format, but a caller had to know the crate's internals for it to make sense. The new variant names no format, and carries the file the document came from plus the subtree path for `get_as_strict`, so the message reads `Cannot deserialize db/redis in config.toml: missing field \`host\``. `YamlError` continues to report genuine YAML parse failures. Code matching `ConfigError::YamlError` on a deserialization result needs updating.
- Added `Config::outline`, which lists every path in the document with the values replaced by their types (`app/port: <number>`). Eliding the document from `Debug` removed the last practical way to inspect a config, and there was no replacement: `get_strict("")` is rejected as an empty path, and until the re-exports above the `Value` needed for `deserialize::<Value>()` could not be named. Each line is spelled exactly as an accessor takes it — the config's own separator, with keys containing a separator or a backslash escaped — so a line can be pasted straight into `str()`. Values are never printed, which is what makes the output safe to log: `${DB_PASSWORD}` is already interpolated by the time a `Config` exists, and the key *shape* is the part with debugging value. A caller who wants the whole document can deserialize into a `Value` or `Mapping` and serialize that deliberately.
- Documented that environment variable interpolation applies to string **values** only, never to mapping keys — stated in the README, the crate docs and beside `resolve_env_vars`, whose name most implies otherwise, and pinned by a test. The behaviour is unchanged: interpolating keys would make the set of valid config paths depend on the environment, so a path resolving on one machine would silently miss on another.
- **Breaking:** `fmt` / `fmt_strict` now resolve their `keys` with the same path syntax as `base` and every other accessor. `base` went through `get_leaf` — escape-aware, separator-aware, empty-segment-rejecting — while each key was looked up with a raw `Value::get`, so a single call had two different key namespaces: a key containing the separator worked verbatim in `fmt` but required a backslash escape everywhere else. Worse, `key_path` joined `base` and `key` with the separator to build the error message, so a missing key containing a separator was reported as a path that the crate's own accessors could not resolve — the same defect that was fixed when that function hardcoded `/`. Keys are now paths relative to `base`: a single sibling key behaves exactly as before, a key that genuinely contains the separator is escaped as `r"a\/b"` like anywhere else, and a key may reach deeper than one level (`fmt("{}", "db", &["redis/port"])`). Only configs with separator-containing keys passed unescaped to `fmt` are affected.
- **Behaviour change:** a `fmt` key resolving to a mapping or a sequence is now a `FormatError` from `fmt_strict` instead of an empty string in the output. The values were converted with the lenient `to_string`, which renders any non-scalar as `""` — the same gap as `list_strict`'s elements, in the method whose contract is to report. `fmt` (lenient) still returns an empty string for the whole call.
- **Behaviour change:** `list_strict` now checks the sequence's *elements*, not just the container. It type-checked the outer value and then mapped every element through the same lenient conversion `list` uses, which renders anything non-scalar as `String::new()` — so a nested sequence, a nested mapping and a null all came back as `""`, indistinguishable from an element that genuinely is the empty string. `list` doing that is consistent with the lenient half of the API; `list_strict` doing it is not, since reporting rather than papering over is its whole contract. A non-scalar element is now a `FormatError` naming it as `path[index]` — brackets rather than a path, because a sequence element is not addressable as one (`items/0` is a lookup for a key named `0`), so rendering a path would name something the accessors cannot resolve. `list` is unchanged. Configs that relied on non-scalar elements silently flattening will now see an error from `list_strict`.
- **Fixed:** the types this crate's public API hands back can now be named by callers. `Value` (returned by `get` / `get_strict` and `ConfigHandle::get`), its payload types `Mapping`, `Sequence` and `Number`, and `Error as YamlError` are re-exported from `yaml_serde`; `serde_json::Error as JsonError` and `toml::de::Error as TomlError` are re-exported under their respective features. Only `Config`, `ConfigHandle` and `ConfigError` were exported before, so a downstream crate could not name what `get` returned — `Debug` was the only operation available on it — nor bind the public `source` field of any parse-error variant. The alternative was adding `yaml_serde` as a direct dependency and guessing the version this crate resolved; a different one yields two incompatible `Value` types whose error message names the same path twice. This does not settle whether the value model should become a crate-local type so `yaml_serde` (0.x, where every minor bump is breaking) can be upgraded without a breaking release here — it makes the current API honest and forecloses nothing.
- Added a `tests/` directory — 45 tests across four files, exercising the crate as a consumer rather than from inside. A unit test in `src/` sees private fields and links against the crate's own dependency graph, so it cannot observe what a downstream crate observes; that is why 219 passing tests never surfaced the missing re-exports above. `public_api.rs` covers the re-export surface, `accessors.rs` the lenient/strict reading surface and path syntax, `errors.rs` the `ConfigError` variants callers match on together with their `Display` text and `source()` chain, and `lifecycle.rs` the four constructors, `{env}` resolution, layering, reload, and `ConfigHandle` under concurrent readers and reloaders. Two things are only checkable from here: that `ConfigHandle` is `Send + Sync`, and that the exported `config!` macro expands correctly outside its defining crate, where `$crate` paths resolve differently.
- Added `check.ps1`, which runs the whole pre-release check — clippy (`-D warnings`) and tests across all five feature combinations, the doctests, and the doc build — in one invocation instead of twelve. `-Msrv` additionally runs `cargo +1.85 check`; `-Bench` runs the benchmarks. This project has no CI by design, so these were previously verified by hand at whatever moment someone remembered to run them.
- The declared MSRV is now verified rather than derived. `rust-version = "1.85"` came from reading the dependency tree and had never been compiled against; `cargo +1.85 check` passes with all features and with none.
- **Fixed:** format dispatch by file extension is now case-insensitive, and matches the extension rather than the end of the path. `ends_with(".json")` / `ends_with(".toml")` were byte-exact, but Windows and macOS are case-insensitive by default — there `config.TOML` names the same file on disk as `config.toml` while routing to the YAML parser. The two halves failed differently. `.TOML` produced "deserializing from YAML containing more than one document is not supported", an error pointing at the wrong problem entirely (`[table]` headers read as document separators). `.JSON` was worse: it appeared to work, because JSON is a subset of YAML, silently applying YAML's duplicate-key and number rules instead of `serde_json`'s until a config exercised one of the differences. Matching on the extension also settles the case where the two tests differ: a file named literally `.json` is a dotfile with no extension, like `.gitignore`, and parses as YAML.
- `load_or_create` no longer leaves a broken config file on disk when the defaults do not parse. It wrote first and parsed second, so defaults that were invalid in the file's format — YAML-shaped defaults under a `.toml` filename, say — were already on disk when the parse failed. The file then existed, so the create branch never ran again: every subsequent run read the same broken file and failed identically, and the app could not self-heal. The defaults are now parsed before anything is written, so a failure leaves no file behind and the next run retries the creation. Parsing still follows the file's extension, so the error is unchanged (`TomlError`, `JsonError` or `YamlError`).
- `load_or_create` now creates the file exclusively (`create_new`) instead of with `fs::write`. The not-found check and the write were not atomic and `fs::write` truncates, so a second process starting at the same moment — precisely the first-run scenario the method exists for — could have its freshly-written config silently clobbered by the loser's defaults. Creation now fails with `AlreadyExists` in that race, and `load_or_create` falls through to loading whatever the other process wrote. Internally, the extension → format rule behind `load_auto` moved into a single `format_of` dispatch shared with the new `parse_auto`, so reading a file and validating a string for that same file cannot disagree about the format.
- **Behaviour change:** an overlay can now clear or override a value with null. `merge_values` had a `(base, Value::Null) => base` arm, written so that merging an *empty document* would be a no-op — but the function is recursive, so the arm was reached for every key at every depth. An overlay that set a key to null did not clear it: the null was discarded and the base value survived, with no error raised anywhere. Since a bare `key:` is YAML for null, a `config.local.yaml` written to unset a production credential silently left that credential in place, and an overlay naming a subtree with no body left the entire base subtree standing. The empty-document rule is now applied once per overlay file, in a new `merge_documents` entry point, and the recursion treats null as the ordinary value it is — so "values in the overlay take precedence" is now true for every value type. The key is cleared rather than removed: it stays present holding a null, so `contains` reports `true` while `str` returns `""` and the typed accessors return `None`. An entirely empty (or comment-only) overlay file remains a no-op, which is what keeps it equivalent to an absent `merge_optional` file.
- `merge_required` and `merge_optional` now reject an empty filename with `ConfigError::IoError` (`InvalidInput`), like every loader and `reload_from`. Both went straight to `get_file` with no check. `merge_optional("")` swallowed the caller bug entirely — reading an empty path yields `NotFound`, which is exactly the case it is designed to ignore, so it returned `Ok` and then recorded a dead `Optional("")` overlay that every subsequent `reload()` re-walked. `merge_required("")` did fail, but as `IoError { file: Some("") }`, rendering as the misleading `IO error in : The system cannot find the path specified`.
- Empty filenames are now rejected upfront with `ConfigError::IoError` (`InvalidInput`) by every loader (`load_required`, `load_optional`, `load_or_create`) and by `reload_from`. Previously only `load_required` validated this: `load_optional("")` silently returned an empty config (because reading an empty path yields `NotFound`, which it treated as a missing optional file), and `load_or_create("")` / `reload_from("")` failed later with an OS-level `NotFound` error instead of a clear validation error. The check is now centralized in `load_internal`, and `load_required`'s redundant upfront check has been removed.

## [0.4.0] - 2026-04-01

### Changed

- **Breaking:** `Config::new` is now private. Replace usages with `Config::load_optional` (same signature, same behaviour) or `Config::load_required` if the file must exist.
- **Breaking:** `fmt(format, path)` and `fmt_strict(format, path)` now take an explicit `base: &str` and `keys: &[&str]` instead of a single path with `+`-joined leaf keys. The base path and the leaf keys are now separate arguments, removing the need for a special `+` delimiter and making the API consistent with the rest of the library. Error messages for missing keys now report the full path (e.g. `db/redis/nonexistent`) rather than the raw input string.
- `strfmt` dependency removed — string formatting and filename template substitution are now handled with standard Rust `str::replace` / `str::replacen`. No API changes.
- `reload()` now re-reads the base file and re-applies all overlays registered via `merge_required` and `merge_optional`, in the original order. Required overlays that are missing return an error; optional overlays that are missing are silently skipped. If reloading fails the existing configuration is preserved unchanged.
- Replaced `serde_yaml_bw` with `yaml_serde`

### Fixed

- `Config::default()` is now documented as a shorthand for `Config::load_optional("config.yaml", "/", None)`.
- `parse_path` escape detection now correctly requires the *full* separator to follow a backslash before treating it as an escaped separator. Previously, with a multi-character separator like `::`, a lone `\:` would incorrectly match. The escape syntax `\<sep>` (e.g. `\::` for `::`) now works correctly for all separator lengths.
- `fmt_strict` (and `fmt`) now use `parse_path` for path traversal instead of a raw `split`, so escaped separators in path segments work correctly.
- `parse_path` now uses `separator.chars().count()` instead of `separator.len()` when advancing the iterator past a matched separator, fixing incorrect path splitting for multi-byte Unicode separators.
- `parse_path` byte-slicing with multi-byte UTF-8 separators (e.g. `→`) no longer panics. Uses `len_utf8()` instead of a hardcoded byte offset.
- `reload_from` now clears the overlay chain, matching the documented behaviour. Previously, stale overlays from the original file would be re-applied on subsequent `reload()` calls.
- `str_strict` now returns `Err(FormatError)` for non-scalar values (mappings, sequences) instead of `Ok("")`.
- `list_strict` now returns `Err(FormatError)` for non-sequence values instead of `Ok(vec![])`.

### Added

- `load_optional(filename, sep, env)` — a new public constructor for loading optional config files. Returns `Ok` with an empty config if the file is not found, but still returns `Err` for other failures (invalid YAML/JSON/TOML, permission denied, bad separator) so that a present-but-broken config file is not silently ignored. Replaces the former `Config::new`.
- `load_or_create(filename, sep, env, defaults)` — loads a config file if it exists, or writes the provided default YAML string to disk and returns it as the active config if it doesn't. The defaults string is written as-is, preserving formatting and comments. If the file exists its content is used and the defaults are discarded entirely. Errors on invalid YAML in either the file or the defaults string, or on write failure.
- `merge_required(filename: &str, env: Option<&str>) -> Result<Config, ConfigError>` — deep-merges an overlay file on top of `self`. Accepts an optional `{env}` placeholder in the filename, consistent with the load methods. The resolved filename is recorded; if the file is missing during a `reload()` an error is returned.
- `merge_optional(filename: &str, env: Option<&str>) -> Result<Config, ConfigError>` — same as `merge_required` but silently skips the overlay if the file is missing, both at merge time and during `reload()`. Returns `Err` if the file exists but cannot be parsed.
- `deserialize<T>() -> Option<T>` — deserializes the entire config into a typed struct, returning `None` on failure.
- `deserialize_strict<T>() -> Result<T, ConfigError>` — same as `deserialize` but returns `YamlError` on failure.
- `get_as<T>(path)` — deserializes a config subtree at the given path into any `T: DeserializeOwned`, returning `None` on missing path or deserialization failure.
- `get_as_strict<T>(path)` — same as `get_as` but returns `Result<T, ConfigError>`, with `PathNotFound` if the path is missing or `YamlError` if deserialization fails.
- `serde` added as an explicit dependency (with `derive` feature) so users can use `#[derive(Deserialize)]` without adding `serde` themselves.
- `ConfigHandle` — a thread-safe, cloneable handle to a `Config`, wrapping it in `Arc<RwLock<...>>` for safe sharing across threads.
  - `ConfigHandle::new(config)` — wraps an existing `Config`
  - `From<Config>` — allows `config.into()` as a shorthand
  - `clone()` — cheap clone; all clones share the same underlying config
  - `read()` — acquires a shared read lock and returns a guard giving full access to the inner `Config`
  - `reload()` — acquires a write lock and reloads from disk, re-applying all overlays; returns the same errors as `Config::reload()`
  - Convenience pass-through methods for the most common accessors: `str`, `get_int`, `get_float`, `get_bool`, `contains`
  - A poisoned lock is recovered transparently via `into_inner()` on both reads and writes — the config data remains valid since `Config::reload()` only commits changes at the very end
- Regression test `parse_path_escape_requires_full_separator` covering the multi-character separator escape bug.
- Test `fmt_strict_with_escaped_separator_in_path` covering escaped separators in `fmt` paths.
- Environment variable interpolation in string values. `${VAR}` is replaced with the variable's value; `${VAR:-default}` falls back to the default if unset. Variables are resolved at load time and re-resolved on `reload()`. Missing variables without a default return `ConfigError::FormatError`.
- `config!` macro for concise config loading and merging.
- `From<yaml_serde::Error>` impl for `ConfigError`.
- Compile-time `Send + Sync` assertion for `ConfigHandle`.
- `#[must_use]` on `merge_required` and `merge_optional` to prevent silently discarding the merged result.
- JSON config file support behind the `json` feature flag. Auto-detected by `.json` extension in `load_required`/`load_optional`/`load_or_create`, or loaded explicitly with `load_json(str, sep)` and `load_json_file(filename, sep)`. JSON overlays work with `merge_required`/`merge_optional` and are handled correctly on `reload()`.
- `ConfigError::JsonError` variant for JSON-specific parse errors.
- TOML config file support behind the `toml` feature flag. Auto-detected by `.toml` extension in `load_required`/`load_optional`/`load_or_create`, or loaded explicitly with `load_toml(str, sep)` and `load_toml_file(filename, sep)`. TOML overlays work with `merge_required`/`merge_optional` and are handled correctly on `reload()`.
- `ConfigError::TomlError` variant for TOML-specific parse errors.

### Removed

- `to_list` internal helper (inlined into `list` and `list_strict`).

### Migration guide

```rust
// Before (0.3.x)
let config = Config::new("config.yaml", "/", None)?;
let config = Config::new("config.yaml", "::", None)?;
let config = Config::new("config.{env}.yaml", "/", Some("dev"))?;

// After (0.4.0) — no error if file is missing
let config = Config::load_optional("config.yaml", "/", None)?;
let config = Config::load_optional("config.yaml", "::", None)?;
let config = Config::load_optional("config.{env}.yaml", "/", Some("dev"))?;

// Or, if the file must exist
let config = Config::load_required("config.yaml", "/", None)?;
```

```rust
// Before (0.3.x)
config.fmt("{}:{}", "db/redis/server+port");
config.fmt("postgresql://{}@{}:{}/{}", "database/username+host+port+name");

// After (0.4.0)
config.fmt("{}:{}", "db/redis", &["server", "port"]);
config.fmt("postgresql://{}@{}:{}/{}", "database", &["username", "host", "port", "name"]);
```
